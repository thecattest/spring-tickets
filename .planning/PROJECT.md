# Система продажи билетов через VK бота

## What This Is

Система управления продажей билетов на концерт для команды билетеров через VK бота. Билетеры пересылают боту сообщения клиентов для создания броней, управляют местами (добавление/удаление), регистрируют оплату и получают готовые скрипты для отправки клиентам. Админы дополнительно управляют резервами с комментариями и видят общую статистику. Вся занятость мест хранится в единой базе с атомарными транзакциями для предотвращения конфликтов.

## Current Milestone: v0.2 — Рефакторинг архитектуры бота

**Goal:** Устранить дублирование кода в хендлерах бота (~335+ строк), извлечь переиспользуемые примитивы шагов, консолидировать UI-строки и тексты сообщений, создать центральный роутер с перехватом команд. Улучшить UX навигации: /cancel возвращает на один шаг назад, /exit сбрасывает в IDLE.

**Target features:**
- `bot/constants.py` — StrEnum для всех кнопок (Btn) и команд (Cmd)
- `bot/router.py` — центральный реестр хендлеров с middleware перехвата команд
- `bot/steps.py` — переиспользуемые примитивы: ввод ряда, ввод мест, подтверждение
- `bot/texts.py` — все пользовательские сообщения в одном файле
- `/cancel` → возврат на один шаг назад (не в IDLE)
- `/exit` → полный сброс в IDLE
- Ранняя валидация: проверка наличия мест в ряду ДО запроса номеров мест

## Core Value

**Ни одно место не может быть продано дважды.** Все операции с местами атомарны, уникальность занятости гарантируется partial index на уровне БД, конфликты выявляются до коммита транзакции.

### Out of Scope

- Веб-интерфейс для билетеров — все операции только через VK бота
- Автоматическая оплата через VK Pay API — регистрация оплаты вручную билетером
- Выбор конкретных мест при частичной оплате — детерминированный порядок (row ASC, seat ASC)
- Редактирование резервов обычными билетерами — только админы
- Множественные активные брони на одного клиента — строго одна активная бронь
- Новая бизнес-логика — рефакторинг не меняет действия, только структуру кода и UX навигации
- Phase 6 (статистика) — будет отдельным милестоуном после рефакторинга

## Context

**Текущее состояние бота (v0.1):**
- 7 файлов хендлеров, ~2200 строк кода
- 16 FSM состояний
- ~335+ строк дублированного кода (row validation ×4, seat validation ×4, confirmation ×3, command dispatch ×2)
- Все кнопки — raw strings (10+ кнопок дублируются между keyboards.py и хендлерами)
- Closure wrapper pattern в 6 из 7 файлов хендлеров
- Подробный план рефакторинга: REFACTORING_PLAN.md (Phase 2 + Phase 3)

**Проблемы UX:**
- /cancel сбрасывает в IDLE вместо возврата на шаг назад
- Нет ранней валидации при вводе ряда (бот ждёт номера мест, даже если в ряду нет мест для текущей операции)
- Команды работают только из MAIN_MENU и RESERVE_ACTION (2 dispatch блока), в остальных состояниях игнорируются

**Архитектурный план (из REFACTORING_PLAN.md):**
- `constants.py` — StrEnum для Btn и Cmd, замена raw strings
- `router.py` — декораторы @on_state, @on_command, @on_forwarded, middleware перехвата команд
- `steps.py` — handle_row_input(), handle_seat_input(), handle_confirmation()
- `texts.py` — все сообщения в одном файле с .format() плейсхолдерами

## Constraints

- **Технический стек**: Python 3.14+, vkbottle, Redis, SQLAlchemy 2.0+, SQLite
- **Обратная совместимость**: Все существующие потоки должны работать идентично (кроме улучшений навигации)
- **Нет новой бизнес-логики**: Рефакторинг только — те же DB-операции, те же audit log entries
- **Макет зала**: layout.json не меняется

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| vkbottle вместо aiogram | aiogram только для Telegram, vkbottle специально для VK с встроенной FSM | ✓ Good |
| Redis для FSM состояния | Permanent storage без TTL, очистка только явная | ✓ Good — работает стабильно |
| Детерминированная частичная оплата | Простота реализации, предсказуемость (row ASC, seat ASC) | ✓ Good |
| SeatAssignment.note только для резервов | Комментарии нужны только админам | ✓ Good |
| Один клиент = одна бронь | Упрощает логику, предотвращает путаницу | ✓ Good |
| /cancel → назад на шаг, /exit → IDLE | Более естественная навигация для билетеров | — Pending |
| Router с middleware вместо ручных dispatch блоков | Единая точка входа для всех команд, нет дублирования | — Pending |
| StrEnum для кнопок | Единый источник правды для UI-строк, защита от опечаток | — Pending |
