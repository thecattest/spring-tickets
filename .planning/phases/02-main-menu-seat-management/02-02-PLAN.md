**Handler `main_menu_handler()`:**
For MAIN_MENU state, handle button presses:

1. **"Добавить"** - Transition to AWAITING_ROW (preserve context including from_main_menu=True)
   - Send "Введите номер ряда:" with `keyboard=get_empty_keyboard()`
   - After seats added, seat_addition_menu_handler will check from_main_menu flag to return here

2. **"Удалить"** - Transition to DELETING_ROW
   - First check if reservation has any seats: `seats = db.get_reservation_seats(reservation_id)`
   - If no seats: send "В брони нет мест для удаления." with `keyboard=main_menu_keyboard()`, stay in MAIN_MENU
   - If has seats: send "Введите номер ряда для удаления:" with `keyboard=get_empty_keyboard()`, transition to DELETING_ROW

3. **"Удалить все"** - Transition to CANCEL_CONFIRM
   - First check if reservation has any seats: `seats = db.get_reservation_seats(reservation_id)`
   - If no seats: send "В брони нет мест." with `keyboard=main_menu_keyboard()`, stay in MAIN_MENU
   - If has seats:
     - Count paid_count and booked_count
     - Build message: `f"Отменить бронь {buyer_name}?\n\nВсего мест: {len(seats)} (бронь: {booked_count}, оплачено: {paid_count})"`
     - If paid_count > 0: append `"\n\n⚠️ В брони {paid_count} оплаченных мест. Отмена доступна только админам."`
     - Send with `keyboard=confirmation_keyboard()`
     - Transition to CANCEL_CONFIRM

4. **"Оплата"** - Send message "Функция оплаты будет доступна в следующей версии" (Phase 3)
   - Stay in MAIN_MENU, re-send `keyboard=main_menu_keyboard()`

5. **Unknown text** - Re-show keyboard with "Выберите действие:" and `keyboard=main_menu_keyboard()`

```python
# At the start, after getting buyer_vk_id:
try:
    vk_users = await message.ctx_api.users.get(user_ids=[buyer_vk_id])
    if vk_users:
        vk_info = vk_users[0]
        display_name = f"{vk_info.first_name} {vk_info.last_name}"
    else:
        display_name = f"VK User {buyer_vk_id}"
except Exception:
    display_name = f"VK User {buyer_vk_id}"

# Then use display_name when calling get_or_create_vk_user:
vk_user = db.get_or_create_vk_user(buyer_vk_id, display_name)
```

This ensures VK API is called exactly once, at the start, and the display_name is available for all scenarios.

**Scenario 1: Seller is IDLE, client has NO reservation**
- Current behavior (unchanged): Create new reservation, go to AWAITING_ROW
- Pass display_name to storage context

**Scenario 2: Seller is IDLE, client HAS active reservation**
- NEW: Call `show_main_menu()` instead of creating new reservation
- Pass display_name (already fetched above) to show_main_menu

**Scenario 3: Seller is NOT IDLE (working with another client)**
- NEW: Check if forwarded message is from SAME client as current context
  - If same client: ignore or show "Вы уже работаете с этим клиентом"
  - If different client: Show context switch confirmation

**Context switch flow:**
```python
# Get current FSM state
state_peer = await storage.get(message.from_id)
current_state = state_peer.state if state_peer else "idle"

if current_state != "idle":
    current_context = state_peer.payload
    current_buyer_vk_id = current_context.get("buyer_vk_user_id")

    if buyer_vk_id == current_buyer_vk_id:
        # Same client - do nothing or inform
        return

    # Different client - ask for confirmation
    # display_name already fetched at the top of handler
    current_buyer_name = current_context.get("buyer_display_name", "текущего клиента")

    await message.answer(
        f"Переключиться на {display_name}?\n"
        f"Текущая операция с {current_buyer_name} будет отменена.",
        keyboard=context_switch_keyboard()
    )

    # Check if new client has existing reservation
    existing_reservation = db.get_active_reservation(vk_user.id)

    # Save pending switch info
    await storage.set(
        message.from_id,
        BotState.CONTEXT_SWITCH_CONFIRM,
        # Pending new client info
        pending_buyer_vk_id=buyer_vk_id,
        pending_buyer_display_name=display_name,
        pending_has_reservation=bool(existing_reservation),
        pending_reservation_id=existing_reservation.id if existing_reservation else None,
        # Original context to restore on "Нет"
        original_state=current_state,
        original_context=current_context,
    )
    return
```

**Check for from_main_menu flag:**
```python
async def seat_addition_menu_handler(message: Message, storage: RedisStorage):
    text = message.text.strip()
    context = await storage.get_context(message.from_id)
    from_main_menu = context.get("from_main_menu", False)

    if text == "Добавить еще":
        # Return to AWAITING_ROW (preserve context including from_main_menu)
        await message.answer(
            "Введите номер ряда:",
            keyboard=get_empty_keyboard()
        )
        await storage.set(message.from_id, BotState.AWAITING_ROW, **context)

    elif text == "Готово":
        reservation_id = context.get("reservation_id")
        buyer_display_name = context.get("buyer_display_name")

        if not reservation_id:
            await message.answer("Ошибка: потерян контекст. Начните заново.")
            await storage.delete(message.from_id)
            return

        if from_main_menu:
            # Phase 2 behavior: return to main menu with updated seat list
            from bot.handlers.menu import show_main_menu
            buyer_vk_user_id = context.get("buyer_vk_user_id")
            await show_main_menu(
                message, storage, reservation_id,
                buyer_vk_user_id, buyer_display_name
            )
        else:
            # Phase 1 behavior: generate script and clear state
            try:
                seats = db.get_reservation_seats(reservation_id)
                script = generate_reservation_script(
                    buyer_display_name=buyer_display_name,
                    seats=seats,
                )
                await message.answer(script, keyboard=get_empty_keyboard())
                await storage.delete(message.from_id)
            except db.DatabaseError as e:
                logger.error(f"Error generating script: {e}")
                await message.answer(
                    "Ошибка при генерации скрипта. Попробуйте позже."
                )

    else:
        # Unknown button
        await message.answer(
            "Выберите действие:",
            keyboard=seat_addition_menu_keyboard()
        )
```

**Key points:**
- `from_main_menu=True` is set by show_main_menu() when seller enters via existing reservation
- `from_main_menu` is NOT set (or False) when seller creates new reservation via Phase 1 flow
- This preserves backward compatibility: Phase 1 flow generates script + clears state
- Phase 2 flow returns to main menu for continued management
