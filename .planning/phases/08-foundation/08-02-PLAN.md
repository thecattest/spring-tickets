Create bot/texts.py with module-level string constants extracted from all 7 handler files. Use the complete inventory from RESEARCH.md Pattern 3 as the authoritative list.

Structure the file with these sections (use comment headers):
1. Error messages (ERR_*) — context lost, DB errors, permission errors, validation errors
2. Prompt messages (PROMPT_*) — user input requests
3. Informational messages (MSG_*) — confirmations, status updates
4. Parameterized messages — strings with .format() placeholders

Rules:
- Static strings: plain string assignment (e.g., `ERR_CONTEXT_LOST = "Ошибка: потерян контекст. Начните заново."`)
- Parameterized strings: use named .format() placeholders (e.g., `MSG_SEATS_ADDED = "Добавлено {count} мест:\nРяд {row}, места: {seats}\n\nВсего в брони: {total} мест"`)
- Do NOT use f-string syntax — these are templates called with .format()
- Do NOT include strings from bot/messages.py (those are formatting functions, out of scope)
- Do NOT import any models or other modules (texts.py is pure string constants)
- Include the welcome text and help text from commands.py as WELCOME and HELP constants
- Module docstring explaining purpose

Read each handler file to find all `message.answer("...")` calls and extract the string arguments. Cross-reference with the RESEARCH.md inventory to ensure completeness.

The full list of constants is in RESEARCH.md Pattern 3 — use that as the baseline, but verify against actual handler source code for accuracy of string values.
