  <action>
  TWO files in this task:

  1. **Create bot/handlers/payment.py** — Payment flow handlers:

     Imports: logging, Message, Bot from vkbottle.bot, BotState, RedisStorage, db, keyboards (payment_quantity_keyboard, main_menu_keyboard, get_empty_keyboard), messages (format_payment_confirmation, format_reservation_seats), SeatStatus from models.base, SEAT_PRICE from bot.config, show_main_menu from bot.handlers.menu.

     **Function `start_payment_flow(message, storage, reservation_id, buyer_display_name, vk_message_url=None, vk_message_ts=None)`:**
     - Async function. This is the shared entry point for BOTH receipt and button flows.
     - Fetch seats: `db.get_reservation_seats(reservation_id)`
     - Count BOOKED seats: `booked_seats = [s for s in seats if s.status == SeatStatus.BOOKED]`
     - If `len(booked_seats) == 0`: send "У клиента {buyer_display_name} нет мест для оплаты. Все места уже оплачены." with `main_menu_keyboard()`. Return without state change (stay in MAIN_MENU).
     - Format current seat display using `format_reservation_seats(seats)`
     - Build prompt message:
       ```
       Бронь — {buyer_display_name}

       {formatted_seats}

       Сколько мест оплачено?
       ```
     - Send with `payment_quantity_keyboard(len(booked_seats))`
     - Get current FSM context: `context = await storage.get_context(message.from_id)`
     - Set state to PAYMENT_QUANTITY, preserving existing context (reservation_id, buyer_vk_user_id, buyer_vk_api_id, buyer_display_name) plus adding: `payment_vk_message_url=vk_message_url`, `payment_vk_message_ts=vk_message_ts`
     - Wrap in try/except db.DatabaseError

     **Function `payment_quantity_handler(message, storage)`:**
     - Async function. Handles messages in PAYMENT_QUANTITY state.
     - Get text, context from storage
     - Extract: reservation_id, buyer_display_name, buyer_vk_user_id, buyer_vk_api_id, payment_vk_message_url, payment_vk_message_ts

     - **"Отмена" button:** Return to main menu. Call `show_main_menu(message, storage, reservation_id, buyer_vk_user_id, buyer_display_name, buyer_vk_api_id)`. Return.

     - **Parse quantity:**
       - If text starts with "Все " (note the space): extract number after "Все ", parse as int. This is the "pay all" button.
       - Else: try `int(text)`. If ValueError: send "Выберите количество мест из предложенных кнопок." with current keyboard (need to re-query booked count). Return.
       - Store parsed number as `quantity`.

     - **Validate quantity:**
       - If quantity < 1: error message, return
       - Fetch current BOOKED seats: `seats = db.get_reservation_seats(reservation_id)` then filter BOOKED
       - If quantity > len(booked_seats): send error "Количество мест превышает доступные для оплаты ({len(booked_seats)}). Введите количество от 1 до {len(booked_seats)}:" with `payment_quantity_keyboard(len(booked_seats))`. Return.

     - **Record payment:**
       - `seller_id = db.get_default_seller_id()`
       - Parse vk_message_ts from context: if it's a string, convert with `datetime.fromisoformat()`. If None, leave as None.
       - Call `payment, paid_seats = db.record_payment(reservation_id, quantity, seller_id, vk_message_url=payment_vk_message_url, vk_message_ts=payment_vk_message_ts)`
       - Fetch updated seats to get remaining: `all_seats = db.get_reservation_seats(reservation_id)`, filter remaining BOOKED
       - Format confirmation: `format_payment_confirmation(paid_seats, remaining_booked, payment.payment_amount, buyer_display_name)`
       - Send confirmation message with `main_menu_keyboard()`

     - **Return to MAIN_MENU state:**
       - `await storage.set(message.from_id, BotState.MAIN_MENU, reservation_id=reservation_id, buyer_vk_user_id=buyer_vk_user_id, buyer_vk_api_id=buyer_vk_api_id, buyer_display_name=buyer_display_name, from_main_menu=True)`

     - **Error handling:**
       - Catch `db.InsufficientSeatsError as e`: send "Ошибка: запрошено {e.requested} мест, но доступно только {e.available}." with keyboard. Stay in PAYMENT_QUANTITY.
       - Catch `db.DatabaseError as e`: send "Ошибка при регистрации оплаты. Попробуйте позже." with main_menu_keyboard. Return to MAIN_MENU.

     **Function `register_handlers(bot)`:**
     - Get storage from `bot.state_dispenser`
     - Create wrapper `payment_quantity_with_storage(message)` that calls `payment_quantity_handler(message, storage)`
     - Register: `bot.on.message(state=BotState.PAYMENT_QUANTITY)(payment_quantity_with_storage)`
     - Log registration

  2. **Modify bot/handlers/reservation.py** — Add MAIN_MENU branch for receipt forwarding:

     In `forwarded_message_handler`, the current logic for `current_state != "idle"` goes straight to context switch. We need to ADD a branch BEFORE the context switch logic:

     After line `if current_state != "idle":` and getting `current_context` and `current_buyer_vk_api_id`:

     **Add check for MAIN_MENU state with same client (receipt flow):**
     ```python
     # Check if in MAIN_MENU and same client forwarded a receipt
     if current_state == BotState.MAIN_MENU.value:
         if buyer_vk_id == current_buyer_vk_api_id:
             # Same client forwarded receipt - start payment flow
             from bot.handlers.payment import start_payment_flow
             reservation_id = current_context.get("reservation_id")
             # Extract receipt info from forwarded message
             vk_message_ts = None
             if forwarded.date:
                 from datetime import datetime
                 vk_message_ts = datetime.utcfromtimestamp(forwarded.date)
             await start_payment_flow(
                 message, storage, reservation_id, display_name,
                 vk_message_url=None,  # VK doesn't provide direct message URL in bot API
                 vk_message_ts=vk_message_ts,
             )
             return
     ```

     This branch fires ONLY when:
     - Seller is in MAIN_MENU state
     - The forwarded message is from the SAME client as current context
     - Treated as "receipt forwarding" -> triggers payment flow

     If seller is in MAIN_MENU but forwards from a DIFFERENT client, the existing context switch logic handles it correctly (already works).

     **IMPORTANT:** This new branch must come BEFORE the same-client "Вы уже работаете с этим клиентом" check. Restructure the `if current_state != "idle":` block:

             from bot.handlers.payment import start_payment_flow
