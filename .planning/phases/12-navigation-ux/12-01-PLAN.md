  <action>
Rewrite cancel_handler in bot/handlers/commands.py to implement back-step navigation. The function signature stays the same: `async def cancel_handler(message: Message, storage)`.

**Implementation logic:**

1. Get current state: `state_peer = await storage.get(message.from_id)`. If None or state is idle, send MSG_CANCEL_ALREADY_IDLE and return.

2. Convert state string to BotState enum: `current_state = BotState(state_peer.state.split(":")[-1])` — this handles the "BotState:awaiting_row" format stored by vkbottle.

3. Look up back_state: `from bot.fsm.config import FSM_CONFIG` (lazy import inside function body to avoid circular imports). `config = FSM_CONFIG.get(current_state)`. `back_state = config.back_state if config else None`.

4. Handle three cases:

**Case A: back_state is None AND current_state is CONTEXT_SWITCH_CONFIRM.**
Read `original_state` and `original_context` from `state_peer.payload`. If both exist, restore: `restored = BotState(original_state.split(":")[-1])`, then `await storage.set(message.from_id, restored, **original_context)`, send `texts.MSG_CONTINUE_WITH.format(name=original_context.get("buyer_display_name", ""))`. If original_state is missing, fall through to clear-to-IDLE.

**Case B: back_state is None (IDLE or unknown).**
`await storage.delete(message.from_id)`, send `texts.MSG_CANCEL_FULL` with `commands_keyboard()`.

**Case C: back_state is BotState.IDLE or back_state is BotState.MAIN_MENU (special AWAITING_ROW ambiguity).**
When `current_state == BotState.AWAITING_ROW`:
- Read `from_main_menu` from `state_peer.payload`: `from_main_menu = state_peer.payload.get("from_main_menu", False)`
- If `from_main_menu` is truthy: navigate to MAIN_MENU. Call `show_main_menu(message, storage, reservation_id=state_peer.payload["reservation_id"], vk_user_id=state_peer.payload["buyer_vk_user_id"], buyer_display_name=state_peer.payload["buyer_display_name"], buyer_vk_api_id=state_peer.payload["buyer_vk_api_id"])`. Import `show_main_menu` lazily from `bot.handlers.menu`.
- If `from_main_menu` is falsy: clear to IDLE. `await storage.delete(message.from_id)`, send `texts.MSG_CANCEL_FULL` with `commands_keyboard()`.
- Return after handling (do NOT fall through to generic case D).

**Case D: Generic back_state navigation (most states).**
When `back_state == BotState.MAIN_MENU`: call `show_main_menu` with context data from `state_peer.payload` (same as Case C truthy branch). Import lazily.
When `back_state == BotState.RESERVE_ACTION`: send the reserve action header message. Read `admin_user_id` from payload, query reserves list via `from bot.messages import format_reserves_list` and `from bot.utils import db` (lazy imports). Call `db.get_all_reserves()` to get reserves, `format_reserves_list(reserves)` to format, then send `texts.MSG_RESERVE_ACTION_HEADER.format(reserves=reserves_text)` with `reserve_action_keyboard()`. Import `reserve_action_keyboard` from `bot.keyboards`. Set state: `await storage.set(message.from_id, back_state, **state_peer.payload)`.
For all OTHER back_states: use a prompt lookup dict to send the appropriate message:

```python
_BACK_PROMPTS = {
    BotState.AWAITING_ROW: texts.PROMPT_ENTER_ROW,
    BotState.DELETING_ROW: texts.PROMPT_ENTER_ROW_DELETE,
    BotState.RESERVE_ADDING_ROW: texts.PROMPT_ENTER_ROW,
    BotState.RESERVE_REMOVING_ROW: texts.PROMPT_ENTER_ROW,
}
```

Send `_BACK_PROMPTS.get(back_state, texts.MSG_CANCELLED)` with `get_empty_keyboard()`, then `await storage.set(message.from_id, back_state, **state_peer.payload)`.

**Important details:**
- ALL lazy imports go INSIDE the function body (not at module level) — consistent with existing patterns (see 09-steps, 10-04 decisions).
- Preserve full payload when calling `storage.set()` — pass `**state_peer.payload` to keep reservation_id, buyer info, from_main_menu, etc.
- Keep exit_handler completely unchanged.
- Keep start_handler and help_handler completely unchanged.
- Wrap the entire logic in try/except as currently done, with fallback `texts.MSG_CANCELLED` on error.
