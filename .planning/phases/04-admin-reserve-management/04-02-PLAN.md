  <name>Task 1: Create reserve handler with /reserve command and all FSM flows</name>
  <files>bot/handlers/reserve.py</files>
  <action>
Create `bot/handlers/reserve.py` following the EXACT pattern of `deletion.py`:
- Import style: same as deletion.py (logging, Bot, Message, BotState, RedisStorage, db, parse_seats, layout utils, keyboards)
- Handler signature: `async def handler_name(message: Message, storage: RedisStorage)`
- Registration pattern: `def register_handlers(bot: Bot)` with storage wrappers

The file must implement these handlers:

**1. reserve_command_handler (entry point for /reserve)**
- Check admin status: `is_admin = db.is_user_admin(message.from_id)`
- If NOT admin: send "Управление резервами доступно только администраторам." and return
- If admin: send "Управление резервами:" with `reserve_action_keyboard()`
- Set state to `BotState.RESERVE_ACTION`
- Store admin's AppUser.id in context using `db.get_app_user_by_vk_id(message.from_id)`:
  ```python
  app_user = db.get_app_user_by_vk_id(message.from_id)
  if not app_user:
      await message.answer("Ошибка: ваш аккаунт не найден в системе.")
      return
  await storage.set(message.from_id, BotState.RESERVE_ACTION, admin_user_id=app_user.id)
  ```

**2. reserve_action_handler (RESERVE_ACTION state)**
- "Добавить резерв": prompt "Введите номер ряда:" with empty keyboard, set RESERVE_ADDING_ROW (preserve context)
- "Удалить резерв": prompt "Введите номер ряда:" with empty keyboard, set RESERVE_REMOVING_ROW (preserve context)
- Unknown text: re-show reserve_action_keyboard

**3. reserve_adding_row_handler (RESERVE_ADDING_ROW state)**
- Parse and validate row number (exact same pattern as `deleting_row_handler` in deletion.py)
- Store `current_row` in context
- Prompt for seats: "Введите номера мест для резерва (ряд {row}, мест: {seat_count}):"
- Set RESERVE_ADDING_SEATS

**4. reserve_adding_seats_handler (RESERVE_ADDING_SEATS state)**
- Parse seats with `parse_seats(text)` (same SeatParseError handling)
- Validate seat numbers for row (same is_valid_seat check)
- Store `reserve_seats` in context
- Prompt: "Введите комментарий для резерва:"
- Set RESERVE_COMMENT

**5. reserve_comment_handler (RESERVE_COMMENT state)**
- Get comment from `message.text.strip()`
- If empty: "Комментарий обязателен. Введите комментарий:" and stay in RESERVE_COMMENT
- Get row and seats from context
- Get admin_user_id from context
- Call `db.add_reserve(row, seats, comment, admin_user_id)`
- On success: "Резерв создан:\nРяд {row}, места: {seats_str}\nКомментарий: {comment}"
- Show reserve_action_keyboard, set RESERVE_ACTION (preserve admin_user_id)
- On SeatOccupiedError: show which seats are occupied (same error pattern as reservation.py lines 396-410), set RESERVE_ADDING_SEATS to re-prompt for seats
- On DatabaseError: show error, return to RESERVE_ACTION

**6. reserve_removing_row_handler (RESERVE_REMOVING_ROW state)**
- Same row validation as reserve_adding_row_handler
- Store current_row, set RESERVE_REMOVING_SEATS
- Prompt: "Введите номера мест для снятия резерва (ряд {row}, мест: {seat_count}):"

**7. reserve_removing_seats_handler (RESERVE_REMOVING_SEATS state)**
- Parse and validate seats (same pattern)
- Store `reserve_seats_to_remove` in context
- Show confirmation: "Снять резерв:\nРяд {row}: {seats_str}\n\nПодтвердить?"
- Show confirmation_keyboard(), set RESERVE_REMOVE_CONFIRM

**8. reserve_remove_confirm_handler (RESERVE_REMOVE_CONFIRM state)**
- "Подтвердить": call `db.release_reserve(row, seats, admin_user_id)`
  - On success: "Резерв снят:\nРяд {row}, места: {seats_str}" and if notes exist show "\n\nПредыдущие комментарии:\n" + each note
  - On DatabaseError: show error
  - Return to RESERVE_ACTION with reserve_action_keyboard
- "Отмена": "Отменено.", return to RESERVE_ACTION with reserve_action_keyboard
- Unknown: re-show confirmation_keyboard

**register_handlers(bot: Bot):**
- Register /reserve command handler using `bot.on.message(text="/reserve")(reserve_command_with_storage)`
- Register state handlers for all 7 RESERVE_* states (same wrapper pattern as deletion.py)
- Log "Reserve handlers registered"

CRITICAL IMPLEMENTATION NOTES:
- Use `str(BotState.X)` for any state comparisons (not .value)
- Use `get_empty_keyboard()` when transitioning to text input states
- Always preserve `admin_user_id` in context across all state transitions
- Do NOT use `get_default_seller_id()` — use the admin's own AppUser.id from context
- Import `confirmation_keyboard` from keyboards (already exists)
