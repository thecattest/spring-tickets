# Спецификация VK Бота для продажи билетов

**Дата создания:** 2026-01-24
**Статус:** Детальная спецификация для поэтапной реализации

---

## Обзор

VK бот для билетеров с гибридным интерфейсом (кнопки + текстовые команды). Основной паттерн навигации: **пересылка сообщения клиента = выбор покупателя + отображение главного меню**.

### Технический стек

- **vkbottle** — async VK Bot API library с встроенной FSM
- **Redis** — хранение состояния сессий (незавершенные операции)
- **SQLAlchemy 2.0+** — ORM для работы с БД
- **SQLite** (MVP) → **PostgreSQL** (production)
- **Cron** — расписание напоминаний должникам (каждые 3 дня)

### Ключевые бизнес-правила

1. **Один покупатель = одна активная бронь**
2. **Комментарии ТОЛЬКО для резервов** (обязательны для админов)
3. **Резерв редактируется только админом**
4. **Детерминированная частичная оплата** — места выбираются по возрастанию ряда, затем номера места
5. **Атомарность операций** — все места добавляются/удаляются/оплачиваются одной транзакцией
6. **Макет зала** — JSON загружается при старте бота, валидация мест происходит по макету

---

## Пользовательские роли

### Билетер (обычный)
- Создание/редактирование броней
- Добавление/удаление мест
- Регистрация оплаты
- Просмотр своих броней
- Просмотр списка должников
- Получение скрипта для отправки клиенту

### Админ (билетер + расширенные права)
- Все права билетера
- Управление резервами (добавление/удаление с обязательным комментарием)
- Отмена оплаты (reversal)
- Удаление чужих броней

## Основные сценарии

### 1. Создание новой брони

**Триггер:** Билетер пересылает боту сообщение клиента

**Поток:**

1. **Бот получает пересланное сообщение**
   - Проверяет: есть ли у VK пользователя (автор сообщения) уже активная бронь?
   - **Если да:** Переходит в режим главного меню (сценарий 2)
   - **Если нет:** Продолжает создание

2. **Создание брони**
   ```
   Бот: "Бронь создана для [Имя Фамилия]. Введите ряд:"
   ```
   - FSM state: `AWAITING_ROW`

3. **Ввод ряда**
   ```
   Пользователь: "12"
   Бот: "Введите номера мест через пробел:"
   ```
   - Валидация: ряд должен быть от 1 до 24
   - **Ошибка:** `"Неверный ряд. Допустимые значения: 1-24. Введите ряд:"`
   - FSM state: `AWAITING_SEATS`

4. **Ввод мест**
   ```
   Пользователь: "5 6 7" или "5, 6, 7" или "5-7"
   Бот: "Добавлено 3 места:
   Ряд 12, места 5, 6, 7
   Всего в брони: 3 места

   [Добавить еще] [Готово]"
   ```
   - Валидация:
     - Места от 1 до 28
     - Формат: числа через пробел/запятые ИЛИ диапазон через тире (например: "5-7" = 5, 6, 7)
     - Поддерживаются комбинации: "1, 3, 5-7" = 1, 3, 5, 6, 7
     - Места не должны быть заняты
   - **Ошибка (формат):** `"Неверный формат. Введите номера мест через пробел, запятые или диапазон. Примеры: '5 6 7' или '5, 6, 7' или '5-7'"`
   - **Ошибка (заняты):** `"Места уже заняты: Ряд 12 место 6 (Бронь), Ряд 12 место 7 (Резерв: комментарий). Введите другие места:"`
   - Атомарность: если хоть одно место занято — отклоняются все
   - FSM state: `SEAT_ADDITION_MENU`

5. **Действие после добавления**
   - **[Добавить еще]:** Возврат к шагу 2 (ввод ряда)
   - **[Готово]:** Сохранение брони → Генерация и отправка скрипта (сценарий 7) → Очистка контекста (FSM state → `IDLE`)

**Структуры данных:**
- Redis state:
  ```json
  {
    "user_id": "VK_BILLETEER_ID",
    "state": "AWAITING_ROW",
    "context": {
      "reservation_id": 123,
      "buyer_vk_user_id": 456,
      "temp_row": null,
      "temp_seats": []
    }
  }
  ```

### 2. Главное меню (работа с существующей бронью)

**Триггер:** Билетер пересылает боту сообщение клиента, у которого уже есть активная бронь

**Поток:**

1. **Отображение брони**
   ```
   Бот: "Бронь для [Имя Фамилия]:

   Ряд 12: места 5, 6, 7 (Бронь)
   Ряд 14: места 10, 11 (Оплачено)

   Всего: 5 мест (2 оплачено, 3 забронировано)
   К оплате: [сумма] руб.

   [Добавить] [Удалить] [Удалить все] [Оплата]"
   ```
   - FSM state: `MAIN_MENU`

2. **Действия:**
   - **[Добавить]:** Переход к сценарию 1, шаг 2 (ввод ряда)
   - **[Удалить]:** Переход к сценарию 3
   - **[Удалить все]:** Переход к сценарию 4
   - **[Оплата]:** Переход к сценарию 5

**Конфликт контекста:**
- Если билетер работал с другим клиентом (FSM state != IDLE), бот отправляет:
  ```
  "Сейчас вы работаете с другим клиентом. Завершите текущую операцию или отмените её командой /cancel"
  ```

### 3. Удаление мест

**Триггер:** Кнопка [Удалить] в главном меню

**Поток:**

1. **Запрос ряда**
   ```
   Бот: "Введите ряд для удаления мест:"
   ```
   - FSM state: `DELETING_ROW`

2. **Запрос мест**
   ```
   Бот: "Введите номера мест (через пробел, запятые или диапазон):"
   ```
   - FSM state: `DELETING_SEATS`

3. **Подтверждение**
   ```
   Пользователь: "5 6" или "5, 6" или "5-6"
   Бот: "Удалено 2 места:
   Ряд 12, места 5, 6
   Осталось в брони: 3 места

   [Удалить еще] [Готово]"
   ```
   - Валидация:
     - Формат: числа через пробел/запятые ИЛИ диапазон через тире
     - Места должны принадлежать этой брони и быть в статусе "Бронь" (НЕ оплачено)
   - **Ошибка:** `"Места не найдены в брони или уже оплачены. Доступные для удаления: Ряд 12 места 7. Введите места:"`
   - FSM state: `DELETION_MENU`

4. **Действие после удаления**
   - **[Удалить еще]:** Возврат к шагу 1
   - **[Готово]:** Выход из контекста

**Обновление базы:**
- `SeatAssignment`: установить `released_at = NOW()`, `released_by_user_id = <billeteer>`
- `Reservation.last_activity_at = NOW()`
- Audit log: `action_type = "seat_removed"`, payload: `{seat_ids: [...], reason: "billeteer_action"}`

---

### 4. Удаление всех мест (отмена брони)

**Триггер:** Кнопка [Удалить все] в главном меню

**Поток:**

1. **Проверка прав (если есть оплаченные места)**
   - Если в брони есть хотя бы одно оплаченное место И пользователь НЕ админ:
   ```
   Бот: "В брони есть оплаченные места (2 шт.). Отменить бронь с оплаченными местами может только администратор."
   ```
   - Выход из контекста
   - Если пользователь админ ИЛИ нет оплаченных мест — продолжить

2. **Подтверждение**
   ```
   Бот: "Удалить все места и отменить бронь для [Имя]?
   Будет удалено 5 мест (из них 2 оплачено).

   [Подтверждаю] [Отмена]"
   ```
   - FSM state: `CONFIRM_DELETE_ALL`

3. **Выполнение**
   ```
   Бот: "Бронь отменена. Освобождено 5 мест."
   ```
   - Выход из контекста

**Обновление базы:**
- `SeatAssignment`: установить `released_at = NOW()` для ВСЕХ мест (включая оплаченные)
- `Reservation.state = CANCELLED`
- Audit log: `action_type = "reservation_cancelled"`, payload: `{reservation_id, released_seat_count, paid_seat_count}`

**Важно:** Оплаченные места освобождаются при отмене брони только админом!

---

### 5. Регистрация оплаты

**Триггер:** Кнопка [Оплата] в главном меню ИЛИ пересылка чека от клиента

**Поток:**

#### Вариант A: Пересылка чека (приоритетный)

1. **Получение чека**
   ```
   Билетер пересылает чек от клиента
   Бот: "Получен чек от [Имя]. Бронь:

   Ряд 12: места 5, 6, 7 (Бронь)

   Сколько мест оплачено?

   [1] [2] [Все 3]"
   ```
   - Проверка: есть ли у автора чека активная бронь?
   - **Ошибка:** `"У клиента [Имя] нет активной брони. Создайте бронь перед регистрацией оплаты."`
   - FSM state: `PAYMENT_QUANTITY`

2. **Выбор количества**
   ```
   Пользователь: нажимает [2]
   Бот: "Оплачено 2 места (детерминированный выбор):
   Ряд 12, места 5, 6

   Осталось к оплате: 1 место (Ряд 12, место 7)
   Сумма: [сумма] руб."
   ```
   - Детерминированный выбор: сортировка по (row_number ASC, seat_number ASC), взять первые N
   - **Ошибка (превышение):** `"Количество мест превышает доступные для оплаты (3). Введите количество от 1 до 3:"`
   - Выход из контекста

#### Вариант B: Кнопка [Оплата]

1. **Запрос количества**
   ```
   Бот: "Сколько мест оплачено?

   [1] [2] [3] [Все 3] [Отмена]"
   ```

2. **Аналогично варианту A, шаг 2**

**Обновление базы:**
- `SeatAssignment`: изменить `status = PAID` для выбранных мест
- `Payment`: создать запись с `payment_amount`, `seat_count`
- `PaymentSeat`: связать payment_id с seat_assignment_id
- `Reservation.last_activity_at = NOW()`
- Audit log: `action_type = "payment_recorded"`, payload: `{payment_id, seat_ids, amount, partial: true/false}`

### 6. Управление резервом (только админ)

**Триггер:** Команда `/reserve` или кнопка [Резерв] в общем меню (не привязано к конкретной брони)

**Поток:**

1. **Проверка прав**
   - Если пользователь НЕ админ:
   ```
   Бот: "Управление резервами доступно только администраторам."
   ```
   - Выход
   - Если админ — продолжить

2. **Выбор действия**
   ```
   Бот: "Резерв:

   [Добавить места] [Удалить места]"
   ```
   - FSM state: `RESERVE_ACTION`

#### 6.1. Добавление резерва

1. **Ввод ряда**
   ```
   Бот: "Введите ряд для резерва:"
   ```
   - FSM state: `RESERVE_ADDING_ROW`

2. **Ввод мест**
   ```
   Бот: "Введите номера мест (через пробел, запятые или диапазон):"
   ```
   - FSM state: `RESERVE_ADDING_SEATS`

3. **Ввод комментария (обязательно)**
   ```
   Бот: "Введите комментарий для резерва (обязательно):"
   ```
   - FSM state: `RESERVE_COMMENT`

4. **Подтверждение**
   ```
   Пользователь: "Места для VIP-гостей"
   Бот: "Резерв создан:
   Ряд 5, места 10, 11, 12
   Комментарий: Места для VIP-гостей"
   ```
   - Валидация:
     - Формат: числа через пробел/запятые ИЛИ диапазон через тире
     - Места не должны быть заняты
   - Выход из контекста

**Обновление базы:**
- `SeatAssignment`: создать записи с `status = RESERVED`, `reservation_id = NULL`, `note = <комментарий>`
- Audit log: `action_type = "reserve_added"`, payload: `{seat_ids, note}`

#### 6.2. Удаление резерва

1. **Ввод ряда**
   ```
   Бот: "Введите ряд для снятия резерва:"
   ```

2. **Ввод мест**
   ```
   Бот: "Введите номера мест (через пробел, запятые или диапазон):"
   ```

3. **Подтверждение**
   ```
   Бот: "Резерв снят:
   Ряд 5, места 10, 11, 12
   Предыдущий комментарий: Места для VIP-гостей"
   ```
   - Валидация:
     - Формат: числа через пробел/запятые ИЛИ диапазон через тире
     - Места должны быть в статусе RESERVED
   - Выход из контекста

**Обновление базы:**
- `SeatAssignment`: установить `released_at = NOW()`, `released_by_user_id = <admin>`
- Audit log: `action_type = "reserve_removed"`, payload: `{seat_ids, previous_note}`

### 7. Генерация скрипта для клиента

**Триггер:** Кнопка [Готово] при создании/редактировании брони (автоматически после сохранения)

**Поток:**

1. **Генерация скрипта**
   ```
   Бот: "Бронь сохранена.

   Скрипт для отправки клиенту:

   Добрый день, [Имя Фамилия]! Ваша бронь:
   Ряд 12, места 5, 6, 7
   Ряд 14, места 10, 11

   [Место для вашего текста]

   Всего: 5 мест
   К оплате: [сумма] руб.

   Спасибо за бронь!"
   ```
   - Шаблон включает:
     - Имя клиента
     - Все места из брони (сгруппированные по рядам)
     - Общее количество мест
     - Сумма к оплате (только неоплаченные места)
     - Место для вставки пользовательского текста билетера

2. **Завершение**
   - Очистка контекста (FSM state → `IDLE`)
   - Скрипт можно скопировать и отправить клиенту в VK

**Примечания:**
- Скрипт отправляется после **создания/редактирования брони**, НЕ после оплаты
- Если билетер добавил места через главное меню и нажал [Готово] — скрипт обновляется с учетом всех текущих мест
- Скрипт содержит только забронированные места (не включает оплаченные, так как для них уже был отправлен скрипт ранее)

### 8. Просмотр должников

**Триггер:** Команда `/debtors` или кнопка в админ-меню

**Поток:**

1. **Отображение списка**
   ```
   Бот: "Должники (не было оплат >= 7 дней):

   1. [Имя Фамилия 1]
      Бронь от [дата], мест: 5 (все не оплачено)
      Последняя активность: [дата]

   2. [Имя Фамилия 2]
      Бронь от [дата], мест: 3 (все не оплачено)
      Последняя активность: [дата]

   Всего: 2 должника, 8 неоплаченных мест

   [Обновить] [Закрыть]"
   ```

**Запрос к БД:**
```sql
SELECT r.*, vk.first_name, vk.last_name, COUNT(sa.id) as seat_count
FROM reservations r
JOIN vk_users vk ON r.buyer_vk_user_id = vk.id
LEFT JOIN seat_assignments sa ON sa.reservation_id = r.id
  AND sa.released_at IS NULL
  AND sa.status = 'booked'
WHERE r.state = 'active'
  AND r.last_activity_at <= NOW() - INTERVAL '7 days'
GROUP BY r.id, vk.id
ORDER BY r.last_activity_at ASC
```

### 10. Помощь и навигация

#### Команда `/start`

```
Бот: "Добро пожаловать в систему продажи билетов!

Основные действия:
• Переслать сообщение клиента — создать/открыть бронь
• /debtors — список должников
• /reserve — управление резервами (только админ)
• /help — подробная справка
• /cancel — отменить текущую операцию

Для работы с бронью пересылайте мне сообщения от клиентов."
```

#### Команда `/help`

```
Бот: "Справка по командам:

Работа с бронями:
1. Переслать сообщение от клиента — открыть главное меню
2. В меню доступны: добавить места, удалить, оплатить
3. Места вводятся как: ряд, затем номера
   Форматы ввода мест:
   • Через пробел: 5 6 7
   • Через запятые: 5, 6, 7
   • Диапазон: 5-7
   • Комбинация: 1, 3, 5-7

Оплата:
• Переслать чек от клиента — автоматическая регистрация
• Или через кнопку [Оплата] в меню брони
• После создания брони бот отправит скрипт для клиента

Просмотр данных:
• /debtors — список клиентов без оплат >= 7 дней
• /mystats — ваша статистика продаж

Отмена операции:
• /cancel — сбросить текущее состояние

Админ (если есть права):
• /reserve — управление резервами (добавление/удаление с комментариями)
• Удаление броней с оплаченными местами"
```

#### Команда `/cancel`

```
Бот: "Текущая операция отменена. Все несохраненные изменения отброшены."
```

- Очистить FSM state → `IDLE`
- Удалить временные данные из Redis

## Обработка ошибок

### Категории ошибок

#### 1. Валидация ввода

**Неверный формат ряда/мест:**
```
"Неверный формат. Введите номер ряда (1-24) или места через пробел (например: 5 6 7)."
```

**Места вне диапазона:**
```
"Недопустимые номера мест. Для ряда 12 доступны места 1-28."
```

**Пустой ввод:**
```
"Вы ничего не ввели. Введите номер ряда:"
```

#### 2. Конфликты занятости

**Места заняты:**
```
"Места уже заняты:
• Ряд 12, место 6 — Бронь (клиент: [Имя])
• Ряд 12, место 7 — Резерв (комментарий: VIP-гости)

Введите другие места или измените ряд."
```

**Атомарность:** Если хоть одно место занято — отклоняются все.

#### 3. Бизнес-логика

**Попытка создать вторую бронь:**
```
"У клиента [Имя] уже есть активная бронь (5 мест). Открыто главное меню."
```

**Оплата без брони:**
```
"У клиента [Имя] нет активной брони. Создайте бронь перед регистрацией оплаты."
```

**Количество мест превышает доступные:**

### Граф состояний

```
IDLE (начальное состояние)
  |
  |-- [Пересылка сообщения] --> MAIN_MENU (есть бронь) --> [Добавить] --> AWAITING_ROW
  |                                 |                         |
  |                                 |                         |--> AWAITING_SEATS --> SEAT_ADDITION_MENU
  |                                 |                         |                            |
  |                                 |                         |                            |--> [Добавить еще] --> AWAITING_ROW
  |                                 |                         |                            |--> [Готово] --> IDLE
  |                                 |
  |                                 |--> [Удалить] --> DELETING_ROW --> DELETING_SEATS --> DELETION_MENU
  |                                 |                                                           |
  |                                 |                                                           |--> [Удалить еще] --> DELETING_ROW
  |                                 |                                                           |--> [Готово] --> IDLE
  |                                 |
  |                                 |--> [Удалить все] --> CONFIRM_DELETE_ALL --> IDLE
  |                                 |
  |                                 |--> [Оплата] --> PAYMENT_QUANTITY --> IDLE
  |                                 |
  |                                 |--> [Резерв] (админ) --> RESERVE_ACTION --> RESERVE_ADDING_ROW --> RESERVE_ADDING_SEATS --> RESERVE_COMMENT --> IDLE
  |
  |-- [Пересылка сообщения] --> AWAITING_ROW (новая бронь) --> AWAITING_SEATS --> SEAT_ADDITION_MENU --> IDLE
  |
  |-- [Пересылка чека] --> PAYMENT_QUANTITY --> IDLE
  |
  |-- /cancel --> IDLE (из любого состояния)
```

### Таблица состояний

| State | Описание | Ожидаемый ввод | Следующее состояние |
|-------|----------|----------------|---------------------|
| `IDLE` | Ожидание действия | Пересылка сообщения / команда | `MAIN_MENU` / `AWAITING_ROW` |
| `MAIN_MENU` | Главное меню брони | Нажатие кнопки | Различные |
| `AWAITING_ROW` | Ожидание номера ряда | Число 1-24 | `AWAITING_SEATS` |
| `AWAITING_SEATS` | Ожидание номеров мест | Числа через пробел | `SEAT_ADDITION_MENU` |
| `SEAT_ADDITION_MENU` | Меню после добавления | Кнопка | `AWAITING_ROW` / `IDLE` |
| `DELETING_ROW` | Ожидание ряда для удаления | Число 1-24 | `DELETING_SEATS` |
| `DELETING_SEATS` | Ожидание мест для удаления | Числа через пробел | `DELETION_MENU` |
| `DELETION_MENU` | Меню после удаления | Кнопка | `DELETING_ROW` / `IDLE` |
| `CONFIRM_DELETE_ALL` | Подтверждение отмены брони | Кнопка | `IDLE` |
| `PAYMENT_QUANTITY` | Выбор количества мест для оплаты | Число / кнопка | `IDLE` |
| `RESERVE_ACTION` | Выбор действия с резервом | Кнопка | `RESERVE_ADDING_ROW` |
| `RESERVE_ADDING_ROW` | Ввод ряда резерва | Число 1-24 | `RESERVE_ADDING_SEATS` |

| `RESERVE_COMMENT` | Ввод комментария резерва | Текст | `IDLE` |

- Состояние хранится **перманентно** в Redis (без TTL)

### Очистка при завершении

Все состояния кроме `IDLE` должны сбрасываться при:
- Команде `/cancel`
- Завершении операции (кнопка [Готово])

```python
def is_seat_available(row: int, seat: int) -> bool:
    """Проверка, свободно ли место"""
    return not db.query(SeatAssignment).filter(
        SeatAssignment.row_number == row,
        SeatAssignment.seat_number == seat,
```

#### Получение брони по VK пользователю

```python
def get_active_reservation(vk_user_id: int) -> Optional[Reservation]:
    """Получить активную бронь клиента (если есть)"""
    vk_user = db.query(VKUser).filter(VKUser.vk_id == vk_user_id).first()
    if not vk_user:
        return None

    return db.query(Reservation).filter(
        Reservation.buyer_vk_user_id == vk_user.id,
        Reservation.state == ReservationState.ACTIVE

```

#### Добавление мест (атомарная транзакция)

```python
def add_seats_to_reservation(
    reservation_id: int,
    row: int,
    seats: List[int],
    user_id: int
) -> List[SeatAssignment]:
    """Добавить места к брони (атомарно)"""
    with db.begin():
        # Проверка занятости всех мест
        conflicts = []
        for seat in seats:
            if not is_seat_available(row, seat):
                conflicts.append((row, seat))

        if conflicts:
            raise SeatConflictError(conflicts)

        # Создание всех SeatAssignment
        assignments = []
        for seat in seats:
            sa = SeatAssignment(
                row_number=row,
                seat_number=seat,
                status=SeatStatus.BOOKED,
                reservation_id=reservation_id,
                created_by_user_id=user_id
            )
            db.add(sa)
            assignments.append(sa)

        # Обновление last_activity_at
        reservation = db.query(Reservation).get(reservation_id)
        reservation.last_activity_at = datetime.utcnow()

        # Audit log
        audit_entry = AuditLog(
            action_type="seat_added",
            entity_type="reservation",
            entity_id=str(reservation_id),
            user_id=user_id,
            payload={
                "seat_ids": [sa.id for sa in assignments],
                "row": row,
                "seats": seats
            }
        )
        db.add(audit_entry)

        db.commit()
        return assignments
```

#### Регистрация оплаты (детерминированный выбор)

```python
def record_payment(
    reservation_id: int,
    seat_count: int,
    payment_amount: Decimal,
    user_id: int
) -> Payment:
    """Зарегистрировать оплату с детерминированным выбором мест"""
    with db.begin():
        # Получить не оплаченные места, отсортированные
        seats = db.query(SeatAssignment).filter(
            SeatAssignment.reservation_id == reservation_id,
            SeatAssignment.status == SeatStatus.BOOKED,
            SeatAssignment.released_at.is_(None)
        ).order_by(
            SeatAssignment.row_number.asc(),
            SeatAssignment.seat_number.asc()
        ).limit(seat_count).all()

        if len(seats) < seat_count:
            raise InsufficientSeatsError(seat_count, len(seats))

        # Создать Payment
        payment = Payment(
            reservation_id=reservation_id,
            payment_amount=payment_amount,
            seat_count=seat_count,
            recorded_by_user_id=user_id
        )
        db.add(payment)
        db.flush()  # Получить payment.id

        # Обновить статусы мест + создать PaymentSeat
        for seat in seats:
            seat.status = SeatStatus.PAID

            ps = PaymentSeat(
                payment_id=payment.id,
                seat_assignment_id=seat.id
            )
            db.add(ps)

        # Обновить last_activity_at
        reservation = db.query(Reservation).get(reservation_id)
        reservation.last_activity_at = datetime.utcnow()

        # Audit log
        audit_entry = AuditLog(
            action_type="payment_recorded",
            entity_type="payment",
            entity_id=str(payment.id),
            user_id=user_id,
            payload={
                "reservation_id": reservation_id,
                "seat_ids": [s.id for s in seats],
                "amount": str(payment_amount),
                "partial": seat_count < len(seats)
            }
        )
        db.add(audit_entry)

        db.commit()
        return payment
```

## Audit Log: Каталог типов действий

Полный список `action_type` для ботовых операций:

| Action Type | Entity Type | Описание | Payload Fields |
|-------------|-------------|----------|----------------|
| `reservation_created` | `reservation` | Создание новой брони | `{reservation_id, buyer_vk_user_id, buyer_name}` |
| `seat_added` | `reservation` | Добавление мест к брони | `{seat_ids: [int], row: int, seats: [int]}` |
