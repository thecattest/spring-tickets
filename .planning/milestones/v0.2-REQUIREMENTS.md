## v0.2 Requirements

### Bug Fixes

- [x] **BUG-01**: Fix context switch state restoration — `BotState(original_state)` instead of raw string in `context_switch_handler` (menu.py:325)

### Constants & Texts

- [x] **CONST-01**: Create `bot/constants.py` with `Btn` StrEnum for all button labels, `Cmd` StrEnum for all commands, and `ALL_COMMANDS` frozenset derived from `Cmd`
- [x] **CONST-02**: Update `bot/keyboards.py` to use `Btn.*` instead of raw string literals
- [x] **TEXT-01**: Create `bot/texts.py` consolidating all user-facing prompt and error message strings with `.format()` parameters

### FSM Configuration

- [x] **FSM-01**: Create declarative state machine config — per-state definition of: handler function, allowed input type, validators/checkers, auth guard (admin/seller/any), forward transition(s), back state. Single source of truth for all bot behavior.

### Shared Steps

- [x] **STEP-01**: `handle_row_input()` in `bot/steps.py` — validates row number, checks layout, returns typed result (`RowResult`); used by reservation, deletion, reserve flows
- [x] **STEP-02**: `handle_seat_input()` in `bot/steps.py` — parses seat range string, validates against layout and availability, returns typed result (`SeatResult`); used by reservation, deletion, reserve flows
- [x] **STEP-03**: `handle_confirmation()` in `bot/steps.py` — handles yes/no confirmation input, returns `Optional[bool]`; used by deletion confirm, reserve remove confirm flows

### Router

- [x] **RTR-01**: Create `bot/router.py` with `Router` class that reads FSM config to auto-register handlers with automatic storage injection and auth guards
- [x] **RTR-02**: Universal command interceptor — commands (`/start`, `/help`, `/cancel`, `/exit`) intercepted and handled from any FSM state, not just MAIN_MENU and RESERVE_ACTION
- [x] **RTR-03**: `register_all()` enforces handler registration order: forwarded-message handler first, then command handlers, then state handlers

### Handler Migration

- [x] **MIG-01**: Migrate `bot/handlers/reservation.py` to pure handler functions consumed by FSM config + shared steps
- [x] **MIG-02**: Migrate `bot/handlers/deletion.py` to pure handler functions + shared steps
- [x] **MIG-03**: Migrate `bot/handlers/reserve.py` to pure handler functions + shared steps
- [x] **MIG-04**: Migrate `bot/handlers/commands.py` to pure handler functions
- [x] **MIG-05**: Migrate `bot/handlers/menu.py` to pure handler functions, remove command dispatch elif block
- [x] **MIG-06**: Migrate `bot/handlers/payment.py` to pure handler functions
- [x] **MIG-07**: Migrate `bot/handlers/debtors.py` to pure handler functions
- [x] **MIG-08**: Remove all `register_handlers()` functions and closure wrappers from all handler files
- [x] **MIG-09**: Update `bot/main.py` to use `bot.labeler.load(router.labeler)` instead of per-file `register_handlers()` calls

### Navigation UX

- [x] **NAV-01**: `/cancel` command navigates back one state via back-state defined in FSM config (not to IDLE)
- [x] **NAV-02**: New `/exit` command fully resets FSM state to IDLE (current `/cancel` behavior)
- [x] **NAV-03**: Early row validation — when user enters a row number, immediately check if that row has relevant seats for the current operation (e.g., no booked seats for deletion, no reserved seats for reserve removal) before prompting for seat numbers
