## Сделано: приведение проекта в порядок

Подробный план этапов с обоснованиями — в истории git (`git log --follow -p -- docs/roadmap.md`).

0. **Гигиена:** uv и `uv.lock`, Python 3.12, владелец — настройка `OWNER_VK_IDS`, безопасность `/payments`, единое логирование, ruff + pre-commit, уборка устаревших файлов.
1. **PostgreSQL** вместо SQLite: частичные уникальные индексы (одно активное занятие места, одна активная бронь на покупателя), enum как `VARCHAR` + CHECK, `timestamptz`, скрипт переноса данных из SQLite.
2. **Alembic:** базовая миграция, схема только миграциями, правила expand/contract.
3. **Docker Compose:** образ на uv с `pg_dump` 18, сервисы `postgres`, `redis`, `db-backup`, `migrate`, `web`, `bot`, `cron` с healthcheck и порядком старта, dev-режим с `docker compose watch`. Postgres на Debian с ICU `ru-RU` — правильная сортировка кириллицы.
4. **Фоновые задачи:** supercronic, ежедневный бэкап с отправкой владельцу и бэкап перед миграциями, напоминания о должниках раз в 3 дня; процедура восстановления проверена.
5. **Деплой и легаси:** `deploy/deploy.sh` (`docker compose up --wait`), секреты через Compose `secrets:` и pydantic-settings, heartbeat бота и уведомления владельцу об ошибках; systemd-юниты и скрипты старого деплоя удалены.
6. **Логические баги:** атомарность операций, блокировка брони при оплате, конфликт мест при гонке, запрет изменений отменённой брони, аудит всех изменений и «Проверено» в вебе.
7. **Архитектура:** пакет `tickets` (src-раскладка), сервисы и `unit_of_work`, async SQLAlchemy на psycopg 3, бот на сценариях `flows/` с pydantic-контекстом FSM, тонкие роуты веба, mypy (strict для сервисов и моделей).
8. **Тесты:** `unit` / `integration`, testcontainers, сценарии бота с подменённым VK, тесты гонок, покрытие.

## Бэклог

- [ ] **Watchdog** — задача в `cron` раз в несколько минут: `web /health`, heartbeat бота, Postgres/Redis, место на диске; при **смене** статуса — `notify_owner()` (прошлый статус в Redis), без `docker.sock`. Не заметит падение всего сервера или самого `cron`; при необходимости — Uptime Kuma.
- [ ] **Ограничение частоты уведомлений через Redis** — сейчас интервал хранится в памяти процесса: после перезапуска (например, падающего в цикле контейнера) повтор уходит сразу.
- [ ] **Callback API для бота** вместо Long Poll:
  - vkbottle поддерживает: `BotCallback` + `bot.setup_webhook()` (регистрирует callback-сервер, возвращает код подтверждения и secret), `bot.process_event(event)` — те же роутер и хендлеры.
  - Сделать самим: эндпоинт (`confirmation`, проверка `secret`, быстрый `ok` и обработка в фоне — иначе VK повторит событие), дедупликация по `event_id` в Redis, включить нужные типы событий (`setup_webhook` включает только `message_new`).
  - Отдельное тестовое сообщество обязательно: иначе локальный поллинг и прод-callback обработают одно сообщение дважды.
  - Бот — свой сервис с FastAPI (`/vk/callback`, `/health`), nginx проксирует `/vk/callback`. Healthcheck: `/health` + проверка статуса через `groups.getCallbackServers`.
